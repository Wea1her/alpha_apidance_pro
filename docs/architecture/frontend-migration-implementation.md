# 前端迁移：实施计划（据 Q1-Q126 定案）

日期：2026-09-14。依据：[前端迁移架构规划](frontend-migration.md)（Q1-Q126）与[压力测试与验收方案](frontend-migration-validation.md)。

定位：本文把已确认决策落成可排期的任务、出口条件与待用户确认项。**本文不含未确认决策**；凡是仍待定的都列在第 5 节，不得在实现中自行拍定。

## 1. 目标与非目标

**首版目标**

- 一个网页工作台：共享访问密钥进门，管理员密码才能写；列表层对齐 [alpha.fajiazhifu.cc](reference-alpha-portal.md)。
- 三栏首页：项目池 / 最近动态 / 推特喊单；已排除项目为可收起栏。
- 完整可解释性：每条"为什么推/为什么没推"都能给出原因码、当时阈值、配置版本与原始输入。
- 生成与投递解耦、重启可恢复、不重复付费生成；投递失败不影响网页报告（Q5）。
- Telegram 行为保持不变：频道推送 + 讨论群报告照旧（Q35），只增加"恢复入池"这一条人类入口。

**首版非目标**

- 不做 CLI（Q44c/Q48 修订）、不做邀请码与账号体系（Q71 修订）、不做订阅与付费（Q91）、不做公开门户（Q89）、不做已读状态（Q92）、不做声音提醒（Q94）、不做运维页与网页触发备份恢复（Q61）、不做手动加入项目（Q122 修订）。

## 2. 里程碑与出口条件

沿用并细化架构规划第 10.2 节的 M1-M5。

### M1：存储与审计

交付：PostgreSQL schema；接收记录（含原始 payload、`push_at`、接收序号、解析失败）；逐事件判定记录（原因码、阈值快照、配置版本、分类 type/confidence/reason）；投递记录（与 pushCount 分离的真实发送计数）；项目来源枚举（自然发现/恢复入池/历史导入）；CA 字段（链标识 + 地址）；审计表（永不随 90 天清理删除）；历史导入（3 项目、3 报告、8 映射、消息引用）。

出口条件：

- 所有模拟分支可回溯：未达门槛、去重重复、未升星、分类拦截、分类异常后放行、投递失败、投递状态不确定。
- 历史导入只迁移事实，**不编造**原始事件、分类理由与生成时间；不产生模型请求与 Telegram 发送。
- 分类拦截现在会落库：已排除项目列表从此刻起可累积（历史拦截项目无法补齐，页面须标注）。
- 审计表与业务表同库、同备份，恢复演练覆盖审计。

### M2：任务与投递

交付：单账号有序判定；首次标准/深度任务唯一约束；行锁 + 到期租约（30 s，每 10 s 续租，提交校验执行代次）；任务阶段与心跳；生成/投递解耦；投递重放（预览 + 二次确认 + 必填原因 + 幂等键 + 审计）；**排除动作**（池内项目移入排除池：二次确认 + 在途任务保留 + 后续停止判定与生成）；**恢复流程**（恢复 → 幂等新建标准分析任务 → 不绕过推送阈值；人工排除的恢复必填理由）。

出口条件：

- 首次标准/深度任务各只有一份；Telegram 故障不妨碍网页报告；重启不重复调用已保存正文的模型。
- 恢复入池产生且仅产生一份标准分析任务；重复恢复被唯一约束拒绝并提示既有项目。
- 排除后不再产生新任务与新推送，但已生成报告与已排队投递照常完成（Q133）；被排除项目的接收记录仍按 90 天保留。
- 影子期写入口按 Q87 禁用：写路由返回禁用态并说明原因。

### M3：访问与查询

交付：共享访问密钥登录（环境变量明文配置，长期自动续期 HttpOnly Cookie）；管理员密码写操作门禁（启动校验两者不同值，Q86）；CSRF/来源校验；速率限制；查询 API（星标/来源/状态筛选、游标分页、稳定排序）；健康接口；变更版本号（供前端轮询去重）。

出口条件：

- 无密钥/错误密钥被拒并受速率限制；只读会话访问写路由一律 403。
- 改管理员密码后全部管理员会话失效、仅保留操作者当前会话（Q73）。
- 未登录或会话失效时，接口与实时连接都返回明确错误，不返回空列表。

### M4：前端

交付：三栏首页（项目池 / 最近动态 / 推特喊单）+ 可收起已排除栏；项目详情（全量时间线 + 报告 + 消息链接 + 相关喊单）；判定排查（按账号查为主入口）；运行状态（业务健康指标 + 配置变更时间线）；深浅主题切换；游标分页 + 无限滚动；移动端单栏堆叠。

出口条件：

- 能解释原先 boopfamily/getsweatai 这类"为什么没推"的**已记录**事件；不把无记录当拦截。
- 项目池可按星级、加入监控时间、是否有 CA 筛选；推送计数主列显示展示序号、悬停显示真实发送次数。
- 喊单条目按 6.1 节六行结构渲染；无提及时不显示；显示最后成功检索时间与"立即查一次"。
- 报告作为不可信内容渲染：Markdown 不执行原始 HTML，链接限制安全协议。

### M5：验收与迁移

交付：压测报告、故障演练记录、备份恢复记录、切换与回退步骤、影子对比报告。

出口条件：

- 按验收方案第 2 节：10 个浏览器会话、100 万条留存事件、短时 20 条/秒、列表 p95 ≤ 1s、状态可见 ≤ 3s。
- 影子：≥3 自然日 + 最小样本量（判定事件 ≥N、分类触发 ≥M，首轮校准），星级与去重 100% 匹配、分类差异在阈值内，旧 worker 重启即窗口重置（Q16、Q36、Q39）。
- 备份恢复演练：RPO ≤ 1 小时、RTO ≤ 2 小时，空环境可恢复且旧会话失效。
- 切换：暂停旧 worker ≤10 分钟，新旧唯一执行者；旧 PM2 与 JSONL 只读保留 30 天（Q28）。

## 3. 关键实现顺序

1. schema 与原因码枚举先定稿（M1），因为页面与验收都依赖它；原因码全集须包含分类异常后放行这类分支。
2. 事件采集落库 → 判定落库 → 任务化，先把"能解释"打通，再接投递。
3. 生成/投递解耦与租约在接入前端之前完成，否则页面会建立在会丢更新的存储上。
4. 访问层（密钥 + 管理员密码 + CSRF + 审计）与查询 API 同步做，避免先裸奔后补权限。
5. 前端先做项目池与详情，再做排查页，最后做喊单栏（依赖外部数据源，且待用户配置）。
6. 影子对比工具与静态报告随 M2 一起做，否则 M5 没有证据面。

## 7. 已识别的风险（需在对应里程碑验证）

- **历史不可回溯**：`push_at`、真实推送次数、分类理由与置信度、去重结论、当时配置版本从未落盘；页面必须显式标注"历史数据缺失"，不能显示为"没有发生"。
- **被拦截项目曾不落库**：已排除列表只能从实现后累积；历史拦截无法还原，"恢复"对旧数据的价值有限。
- **恢复是唯一纠错通道**：被误拦的账号不会自行回到监控池；恢复入口不可用即等于漏拦不可纠正。
- **不再有密钥轮换**：访客无法按人撤销，只能清除服务端会话；访问密钥随环境变量进入备份与部署配置。
- **审计不可归因**：写操作不记录操作者身份，只能还原"发生了什么"。
- **推文源成本不可控点**：按条计费 + 用户选择不做用量记录（Q118），翻页或误配可能超支。
- **低事件密度**：现网真实规模仅 3 个项目、3 份归档，影子期最小样本量与"3 天"达标存在无法闭环的可能，需用合成事件补足确定性规则覆盖并如实记录（Q57）。
